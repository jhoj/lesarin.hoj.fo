# Pinned exactly, because deploy/deploy.sh runs `pip install -r requirements.txt`
# on the VPS on every deploy. With open ranges, a release published upstream
# between two deploys could change production without a single commit here —
# and CI would have been testing a different resolution than the server ran.
#
# To upgrade something:
#   pip install -U <package>          # in a scratch venv
#   pip freeze | grep -i <package>    # copy the version back here
#   pytest -q                         # and let the PR's CI confirm it
#
# Verified installable on Python 3.11 (what CI uses) through 3.14.
